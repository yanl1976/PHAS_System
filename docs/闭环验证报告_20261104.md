## 二、本轮发现并已修复的缺陷

### 阻断级（影响出账）

**1. 一张作废单可以永久挡住整月导出**
- 现象：勾稽把「无人员归属」判为 error，而该检查遍历了**未入账**单据（含已驳回）。
  库里 8 月单 6 被驳回、其中一行没识别到人 → `balanced=False` → `/api/export` 一直 400。
- 后果：要么导不出工资表，要么被迫关校验/绕过，校验形同虚设。
- 修复：`reconcile()` 把账内（已确认）与账外（未确认/驳回）分开判 ——
  error 只对账内，账外单列为 `UNASSIGNED_OFFLINE` 提示；`out_of_period/zero_qty/abnormal` 同样只判账内。
- 验证：`test_closure_audit.py [2][3]`。

**2. 核算期锁定能被绕过（两个后门）**
- `POST /sheets/batch-verify` 不查锁定；`POST /sheets/{id}/reopen` 不查锁定。
- 后果：号称"月结锁账"，实际批量页签和"重新打开"都能改已出的账。
- 修复：两处都加锁定检查；批量入口把锁定单据跳过而不是照样确认。
- 验证：`[5]`（单张确认/重开 400、批量跳过）。

**3. 驳回单据后，任务的"实报工时"不清零**
- 根因：`Session` 是 `autoflush=False`，`reject` 里改完状态直接调 `refresh_task()`，
  那条 SELECT 读到的还是旧状态 → 算出来仍是旧值，再被 commit 固化。
- 后果：任务卡上挂着一个"由已作废单据凑出来的实报工时"，且永远不会自愈。
- 修复：状态变更后先 `db.flush()` 再重算。

### 一致性级（数字会悄悄错）

**4. 重开/驳回不改任务的物化字段**
- 原先只有「改挂」会重算 `sheet_count/actual_hours`，重开、驳回都不重算。
- 修复：两处都调 `refresh_task`。

**5. 批量确认、自动归集没有留痕**
- 单张确认写了 `audit_log`，批量确认没写；单据确认时"自动归到哪个订单"也没写。
- 后果：月底问"谁批的这批单"、"这张单为什么算在这个订单上"，查不到。
- 修复：两处补齐审计（`field=status` / `field=task_id`，带操作人与新值）。

**6. 作废单让整个期间永远锁不上**
- `lock_period()` 用 `status != verified` 判"还有未完成的"，而作废单永远不是 verified。
- 后果：错一张单 → 这个月结不了账。
- 修复：`status notin ("verified","rejected")`。

**7. 锁定/解锁没有操作人与原因**
- 解锁等于"把已出的账重新打开"，是内控里最该留痕的动作，原先只要一行 200。
- 修复：`lock/unlock` 接受 `user`，`unlock` 另收 `reason`，都写 `audit_log(entity="period")`。

**8. 产品/件名为空，系统一声不响**
- 已有 `UNKNOWN_PROCESS` 兜工序，但产品/件名为空没有任何告警。
- 后果：汇总里多出一列"未填"，成本/工艺分析查不到这几行，而没人会主动去找原因。
- 修复：新增 `MISSING_PRODUCT` / `MISSING_PART` 两个 warn 级告警（核对页可见）；
  确认回执里追加一条"有 N 行归集维度不全"。

**9. 确认回执的 warnings 前端没接**
- 后端算了"件名没有已发布工艺""维度不全"等提醒，`ReviewView` 只弹成功提示就丢掉。
- 修复：确认成功后弹窗列出跟进项。

### 工程级

**10. 联调脚本会把测试数据写进生产账**
- 实测：跑一次 `test_e2e.py` → +4 张单据、+1 个批次、+1 个任务；
  **把库里已有的 7 张真实单据的确认人改成 tester、确认时间改成当下**；
  还会在「历史导出」里留下含测试数据的归档文件。
- 修复：只确认自己上传出来的单；跑完自动清理（单据/明细/图片文件/批次/空任务/导出归档）；
  `--keep` 可保留现场。实测跑完库回到 8 单据 / 1 批次 / 6 任务。

**11. 测试脚本一直跑在真实库上**
- 其余 15 个脚本自带清理，但清理逻辑本身也是代码，一样可能有 bug。
- 修复：新增 `run_tests.py`，用 SQLite 在线备份 API 拷一份库到临时目录，
  `WT_DB_URL` 指过去再跑，跑完删副本。**生产库零写入。**
- 附带新增 `recalc_tasks.py`：任务物化字段漂移的体检与修复（`--fix` 才写）。

## 四、需要你决策的 7 项（我没有擅自改）

按"业务影响 ÷ 改动代价"排序：

**A. 单据没有"删除/彻底作废"入口（建议优先）**
现在错拍的、重复上传的单据只能 `reject`（作废），它仍占着台账、占着批次、占着图片。
我这次清理测试数据只能直连数据库删 —— 说明这条路在界面上不存在。
建议：给单据加 `void`（作废且不计入任何统计、不参与锁定检查、可筛选隐藏），
或提供物理删除（限管理员 + 强制留痕 + 连带重算任务）。**要不要做、做哪种，你定。**

**B. 任务"实报工时"的口径**
现状：任务实报 = 所有非驳回单据工时（**含还没核对的**）；月度汇总只算已确认。
同一批单据在任务卡和汇总表上会是两个数（当前差 8.33h）。
两种一致的方向：① 实报只算已确认，另列"待核对 N 张"；② 保持现状，但任务卡上标明含待核对。
我倾向 ①（未核对的工时可能还会改，不该进"实报"），但这会改动业务口径，需你确认。

**C. 3 行已确认数据缺归集维度**
`#4/1` 缺产品、`#5/1` 缺产品+件名+工序、`#7/1` 缺件名。
其中 `#5` 是整页识别几乎失败（表头都没读出来）却仍然确认入账的——25 小时记在"未填"工序上。
建议：这三行回核对页补录；另外**是否把"工序为空"从 warn 升级为 block**（不许确认），请你定。

**D. 跨期单据只在勾稽里提示**
`#5/1` 完工日期 2026-07-15，却记在 9 月期间。现在确认时不拦，只在勾稽里 warn。
建议：确认前弹一次二次确认（"这行日期不在本期，确认要计入 9 月吗"）。

**E. 没有登录与权限**
`audit_log.user` 由前端传字符串，任何人都能写成别人的名字。单机内网可接受，
一旦多人用，留痕就等于没有。建议至少加"操作人口令"或简单账号。

**F. 备份策略缺失**
SQLite 是 WAL 模式，直接 `cp worktime.db` 拷出来的是**没有表的空壳**（我这次就踩了）。
建议加每日 `VACUUM INTO 'backups/worktime-YYYYMMDD.db'` + 保留 30 天，一分钟的事。

**G. 测试与生产同库（已缓解，未根治）**
本轮已加 `run_tests.py` 走副本；但脚本默认仍是生产库。
建议后续把"必须用副本"做成默认，直连生产要显式加 `--allow-prod`。

# 第二轮：7 项待决策已全部实现（同日）

第一轮末尾列出的 A–G 七项，按推荐方案全部落地。下表是「原来会怎样 → 现在怎样」。

| 项 | 原来的问题 | 现在的行为 |
|---|---|---|
| **A 作废/删除** | 错拍、重复上传只能 reject，仍占台账/批次/图片，清理只能改库 | 核对页与台账页都有「作废 / 恢复 / 删除」；删除前整单快照写审计、已确认与锁定期一律不许删 |
| **B 实报口径** | 任务实报含待核对单据，与汇总两个数 | 任务 `actual_hours` 只算已确认，`pending_hours/pending_count` 单列「待核对」，任务页、抽屉、体检三处同口径 |
| **C 维度告警** | 「工序为空」只是提示，缺维度能一路走到汇总「未填」 | 工序为空升级为**阻断**（可强制确认）；已确认单据新增「补录维度」窄通道（必填原因、逐项留痕、不许清空） |
| **D 跨期确认** | 7 月的单混进 9 月账，没人知道 | 确认返回 `409 OUT_OF_PERIOD`，前端弹「完工日期不在本期」二次确认；批量确认跳过并提示单张处理 |
| **E 身份** | 审计操作人是前端传的字符串，可冒名 | 登录 + HMAC 令牌；审计 `user` 由服务端 ContextVar 统一改写，请求体里的 `user` 不再被采信；单工位可用 `WT_TRUST_LOCAL=1` 免登录 |
| **F 备份** | WAL 下 `cp` 得到空表壳 | `VACUUM INTO` 在线快照 + `quick_check` + 核心表行数校验；CLI（`scripts/backup_db.py`）与管理页按钮共用同一实现 |
| **G 测试库** | 测试脚本默认连生产库 | 脚本名以 `test_` 开头自动拷副本到临时目录，跑完删除；回归输出打印「生产库未被写入」 |

## 本轮新发现并修掉的问题

1. **新增 block 规则会让历史告警「过期」**：库里存的仍是旧规则的 flags，台账显示旧徽标、体检误报漂移。新增 `scripts/revalidate_all.py`（默认预演，`--apply` 落库），已把全库对齐。
2. **生产任务页整页白屏**：抽屉头部 `detail.notices` / `taskLocked` 未判空，`detail` 为 null 时渲染抛错，整个 RouterView 挂掉。已补守卫。
3. **组合台账把「有已发布路线」的组合藏起来**：历史工时行全部停用时，`active` 判断把该组合过滤掉，即使它有一条已发布路线在用。修好后组合数 888 → 889。
4. 管理页两张卡表格列超宽被裁（时间列折行、「停用」按钮出界）；跨期弹窗文案重复；标准工时偏差显示「相差 0.0 倍」（0.5 对 12 应为「-96%」）。
