# 工资核算：工时单价与工时工资表

> 2026-11-04 第十三轮。本文只讲「工时怎么变成钱」这一层；
> 报工单的识别、核对、工时重算见《工时识别系统设计方案》。

## 1. 业务链条

```
工艺卡（定额：该怎么干、几道工序、单件多少工时）
   ↓ 工人照卡干活
报工单（实际：合格 / 返修 / 废品、单件与合计工时、检验员、日期）
   ↓ 系统重算：合计工时 = 合格件数 × 单件工时
报工工时（人 × 工序 × 月）
   ↓ × 该月生效的工时单价
工时工资
```

一次概念纠正（用户 2026-11-04 明确）：**导入识别的《加工路线单》在业务上就是报工单**。
纸面名字不变，系统里菜单按「报工」说话（单据台账 → 报工台账），
但**支付对象是工时，不是单据**：单据只是工时的载体。

## 2. 数据模型：单价按「生效月」留档

`worker_rate`

| 列 | 含义 |
| --- | --- |
| `worker_id` | 人员 |
| `effective_ym` | 生效月 `YYYY-MM` |
| `rate` | 元/小时 |
| `note` | 备注（如「2026 年调薪」） |
| `updated_at` | 最后修改时间 |

唯一约束 `(worker_id, effective_ym)`：同一人同一月只留一条。

**为什么不在 `worker` 上放一个「当前单价」**：工资要能回溯。9 月调过价，
8 月的工资表必须还按 8 月的老价算得出来。只留当前值的话，一改价，历史工资表
跟着变，而工资发出去是不会变的。

取价规则：`effective_ym <= 核算月` 里**最新**的一条；一条都没有 = 未设单价。

## 3. 计算口径

```python
# app/domain/wages.py
工时   = monthly_summary() 里该人的 hours         # 合格件数 × 单件工时
单价   = rate_index(db, ym).get(worker_id, 0)
金额   = round(工时 × 单价, 2)                    # 按人四舍五入到分
合计金额 = Σ 各人金额                              # 不拿总工时 × 平均单价
```

最后一条容易被忽略：总工时 × 加权平均单价会与「各人金额相加」差几分钱，
财务对不上就会整表退回。所以合计永远由分项相加得到。

工时口径与《月度汇总》一致，不另算一套 —— 工资说 180 小时、汇总说 176 小时，
这种账在车间里永远说不清。

**返修 / 废品不产生工时**（`REWORK_FACTOR` / `SCRAP_FACTOR` 默认 0），
因此也不产生工资。若车间实际是「返修给半价」，改这两个系数即可，
不需要动工资逻辑（口径说明里会把系数印出来）。

## 4. 两个「不能静默」的判断

| 情况 | 系统怎么做 | 为什么 |
| --- | --- | --- |
| 有人没设单价 | 金额记 0，但标 `has_rate=false`；工资页顶部横幅列出人数与工时；导出写「未设单价」四个字 | 没单价 ≠ 工资 0 元，是算不出来。静默当 0，等于白干 |
| 本月还有报工单没确认 | 顶部横幅提示「这份工资表只是半成品」，给「去核对」入口 | 确认前发钱，月底补单就变成补不完的补丁 |

### 4.1 这三条同时是**导出闸门**（2026-11-05）

界面横幅只是提醒，导出才是发钱的依据，所以 `/api/wages/export` 直接拦：

| 拦住的情况 | 返回 |
| --- | --- |
| 勾稽有 error（明细合计≠人员合计、行合计≠件数×单件、账内有行没归属人） | 400，附具体错项 |
| 还有识别单在待核对 | 400，写明几张 |
| 有人没设工时单价 | 400，写明几人、多少小时会算成 0 元 |

口径与工时汇总导出（`/api/export`）一致 —— 那边早就是「勾稽不过不许导」，
工资表以前却照样能导，等于两套标准。想先看版式/核对数据用 `preview=1`，
与汇总导出的约定相同；界面会把理由摊开，让人选「导出预览版」还是「回去处理」。

「待核对」只算 `status=recognized`：作废（`rejected`）是**已经处理完**的结果，
不是待办 —— 把它算进去，一张废单就能永久挡住整月导出，最后逼人去关校验。
校验一旦能被绕过，等于没有校验。

## 5. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/wages?ym=` | 月度工资：人、工时、单价、金额、工序构成 |
| GET | `/api/wages/rates?ym=` | 单价设置卡片（未设的排前面，同组按车间→工种→姓名） |
| PUT | `/api/wages/rates` | 按生效月写单价（管理员）；同月再写=改这条，并进审计；锁账月份拒收 |
| GET | `/api/wages/export?ym=&preview=` | 导出工时工资表 xlsx；`preview=1` 跳过闸门 |

审计：`entity="worker_rate"`、`field="rate@YYYY-MM"`、旧值/新值/操作人。
操作人由服务端从令牌解出，与其它写操作同一条链路。

## 6. 导出：原格式不动，右侧追加两列

参照 `doc/` 里车间在用的月度工时表（如 `doc/2026年9月2车间工时1.xlsx`）：

```
每人一张表            标题「YYYY年M月份个人工时工资表」
                     第二行 姓名 / 工种 / 单价 / 工时·工资
                     表头前 11 列与原表逐字一致：
                     序号 | 产品名称/代号 | 批次 | 件名 | 工序 | 合格件数 |
                     单件工时 | 合计工时 | 完成时间 | 检验员 | 备注
                     + 合计(时:分)    ← 原有修正列（原表 24h 会显示成 N days）
                     + 工时单价 | 工时工资   ← 本次新增
总工时                原样保留（人 × 工序 的工时拆分）
工资汇总              新增：序号 | 人员 | 工种 | 工时 | 工时(时:分) | 工时单价 | 工时工资 + 总计
口径说明              新增：工时口径 / 工资公式 / 单价来源 / 未设单价人数 / 合计金额
```

为什么「追加」而不是「重排」：这张表是车间主任和财务拿去跟历史月份对比的，
列一挪、顺序一变，他们就得重新学一遍怎么读。

## 7. 界面

- **工资核算**（新增菜单，`/wages`）：KPI（合计工资 / 报工工时 / 人数 / 加权平均单价 /
  未设单价人数）、人员明细表（工时、单价、金额、工序构成、明细行数）、导出按钮、
  以及一段「这张表怎么来的」口径说明。
- **系统管理 → 工时单价**（新增卡片）：所有在用人员，未设的排前面，可搜索、
  可批量填、只提交改动行。卡片上直接显示「已定价 5 / 40 人（未设 35）」。

## 7.1 「导出工资表点击没反应」是怎么来的（2026-11-04 修复）

最初的实现是「axios 取 blob → `URL.createObjectURL` → `<a download>` 点一下」。
在干净浏览器里能跑通（Playwright 实测能收到 download 事件），但它有两个坑，
而且**失败时完全静默** —— 用户看到的只有「按钮像坏的」：

| 坑 | 后果 |
| --- | --- |
| `blob:` 下载被内嵌浏览器 / 受限预览环境拦掉 | 不下载、不报错、无提示 |
| `doExport` 没有 `catch` | 一旦请求抛错，`finally` 复位 loading，界面零反馈 |

现在改成**同源 URL 下载**，与「导出与勾稽」页的 `window.open` 走同一条路：

```js
// 浏览器自己处理 attachment 响应，文件名由后端 Content-Disposition 决定（中文不乱码）
const a = document.createElement('a')
a.href = api.wageExportUrl(store.ym, includeUnverified.value)
a.target = '_blank'      // 关键：接口报错时返回 JSON 而非附件，
                         // 同标签导航会把整个 SPA 跳到那串 JSON 上，页面就"丢"了
document.body.appendChild(a)
a.click()
document.body.removeChild(a)
```

配套三件事：

1. **空月份先拦住**：该核算期没有可核算数据时直接提示，不发请求 —— 那种情况导出的
   结果是一张只有表头的空表，比报错更让人以为「导出坏了」。
2. **明确提示**：点完立刻 toast「已开始生成工资表，稍候在浏览器下载栏查看」。
3. **兜底入口**：顶栏新增「最近导出」，列出 `data/exports` 里最近的工资表
   （文件名 / 大小 / 生成时间 / 下载），关掉页面也能事后拿文件。
   下载真被拦掉时，从这里点链接照样能拿到 —— 走的是静态 `/media/exports/`，不经过 blob。

顺带修掉一处测试污染：`POST /api/wages/export` 每被调用一次就往后端 `EXPORT_DIR` 落一个
文件，`test_wages.py` 跑一遍就在生产导出目录里留一串 `2099-01工时工资表_*.xlsx`，
还会出现在界面的「最近导出」里。测试现在把 `export_excel.EXPORT_DIR` 指向临时目录。

## 8. 顺手修掉的一个真 bug

`require_admin()` 在本机免登录模式下一直判 401：中间件把身份写成「本机操作员」
（虚拟名，库里没有账号），函数查不到人就当「登录失效」。
后果是单机部署里「账号」卡片根本打不开 —— 以前没人测到，因为浏览器里都会先登录。
现在只有「身份来自本机免登录」这一条路径放行，带令牌来但查不到人的仍然拒绝。

## 10. 边界（明确的「不做」）

- 只算**工时工资**，不含补贴、扣款、社保、个税 —— 这些是财务口径，系统只出「工时 × 单价」。
- 不按工序设不同单价（现状是「按人一个价」）。若确有「同一人不同工序不同价」，
  应另做工序单价表，而不是在这张表上加字段。
- 不做发放：导出 xlsx 交给财务，系统里不留「已发」状态。
